# kindle_sale_notification

Kindle で **サンプルだけ落としてある「気になる本」** がセールになったら教えてくれる PoC。

サンプルをダウンロードした本 ＝ 買うか迷っている本。そのリストを Amazon のライブラリから
自動で集めて、価格とポイント還元から**実質割引率**を出し、買い時を **macOS に通知**する。

Amazon の全書籍を毎日クロールするのは重いので、**セール情報の RSS を GitHub Actions で見張り、
関係のありそうなセールが始まったときだけ手元で価格チェックを回す**構成にしている。

```
GitHub Actions（1時間毎・RSS だけ取得）
  └─ 文庫/新書/選書 などのキーワードに該当する新着記事を検知
       └─ Issue を立てて通知（メール / GitHub モバイル）
            └─ 手元の Mac で ./run.sh all → 実質割引率を計算 → macOS 通知
```

実行イメージ（数値は実行時点による）:

```
$ ./run.sh all
▶ 1/4 サンプル一覧を更新...
  [全書籍(ユニーク)] 196
  [全サンプル] 148
▶ 2/4 価格取得（148 件）...
  [1/148] B09HQJPY27 Kindle￥880 / 紙￥957 / 440pt 実質54% 🔥SALE(実質54%)  極夜行 (文春文庫)
  [2/148] B0H1GB6HSG Kindle￥2156 / 紙￥2200 / 22pt 実質3%  ノマドという生き方
  ...
  [セール中] 21 件（うち紙価格あり 20 件）
  [404] 0 件（フォールバック解決 2 件）/ [価格取得不可] 0 件
▶ 3/4 差分検知・通知...
  [通知対象] 2 件
  🔔 [B09HQJPY27] Kindle￥880 440pt 実質54%  極夜行 (文春文庫)
      理由: 新規セール / 値下がり ￥968→￥880
▶ 4/4 表を出力...
✅ 完了: poc/out/report.md / report.csv
```

`report.md` は割引率の降順で並ぶ:

| 割引率 | 紙の本の価格 | Kindle価格 | 獲得ポイント | タイトル | 著者、訳者 | 発売日 |
| --- | --- | --- | --- | --- | --- | --- |
| 54% | ￥957 | ￥880 | 440pt | 極夜行 (文春文庫) | 角幡 唯介(著) | 2021/10/6 |
| 3% | ￥2,200 | ￥2,156 | 22pt | ノマドという生き方――旅暮らしの人類学 教養みらい選書 | 左地亮子(著) | 2026/6/10 |

## セールの判定基準

Kindle のセールは **値引きより「ポイント高還元」で行われることが多い**。
サンプル 149 冊を実測した回では、取り消し線による値引きは 0 件だったのに対し、
ポイント高還元（還元率 30〜50%）は 40 件あった。そこで値引きと還元を 1 つの指標に統合する。

```
実質割引率 = (紙の本の価格 − Kindle価格 + 獲得ポイント) / 紙の本の価格
セール     = 実質割引率 >= 20%          # poc/lib/parsePrice.js の SALE_THRESHOLD
```

紙版が存在しない本は基準価格が無いので、ポイント還元率（ポイント / Kindle価格）で代替する。
通常の本は還元率 ~1%、高還元セールは 30〜50% と明確に分離できる。

## セットアップ

必要なのは Node.js だけ（Chrome は Puppeteer が同梱版を落とす）。

```sh
npm install
./run.sh login        # 初回のみ。開いた Chrome で Amazon に手動ログイン（2FA も手動）→ Enter
./run.sh samples      # ライブラリを巡回してサンプル一覧を作る
```

ログインセッションはプロジェクト内の `.chrome-profile/` に永続化され、2 回目以降は不要。
普段使いの Chrome を終了する必要はない（専用プロファイルなので競合しない）。

## 使い方

```sh
./run.sh               # メニューから選択
./run.sh all           # 一覧更新 → 価格取得 → 差分検知・通知 → 表の出力
./run.sh samples       # ライブラリを巡回してサンプル一覧を更新
./run.sh batch 25      # 25 件だけ価格取得
./run.sh detect        # 前回との差分を検知して通知
./run.sh report        # 表（Markdown / CSV）を出力
./run.sh price B0CYZ95626   # 1 冊だけ価格を確認
./run.sh feed --dry    # セール情報フィードを手元で確認（Actions と同じ判定）
```

個別の npm スクリプトは `package.json` を参照。`npm run poc:detect -- --dry` は
通知も履歴更新もせず結果だけ表示する（状態を変えない確認用）。

`./run.sh all` は **Chrome のウィンドウを開いて 10 分前後かかる**（Amazon がヘッドレスを
弾くため避けられない）。セール検知の通知を受けたときに回す想定。

## セール検知（GitHub Actions）

`.github/workflows/sale-watch.yml` が 1 時間ごとに RSS を取得し、
`feed.config.json` のキーワードに該当する**新着**記事があったときだけ Issue を立てる。
Issue は自分にアサインされるので、メールと GitHub モバイルに通知が飛ぶ。

監視しているフィード（`feed.config.json` で変更可能）:

| フィード | 性格 |
| --- | --- |
| [きんどう](https://kindou.info/feed) | セール情報専門で速報性が高い。マンガ・ラノベ寄り |
| Google ニュース検索 | `Kindle セール (文庫 OR 新書 OR 学術)` のクエリ。メディア記事を拾う |
| はてなブックマーク検索 | 個人ブログのセール紹介記事を拾う |

**キーワードの設計が肝心。** 「50%還元」のような語はマンガのセール記事にほぼ毎回付くため、
1日 6〜10 回発火してしまう（実測で 9/20 件が該当）。既定では
`文庫 / 新書 / 選書 / 学術文庫 / ブルーバックス / 岩波 / 早川 / 文春 / 新潮 / 均一 / 半額` など
**自分が読む帯**に寄せ、`ラノベ / 異世界 / コミック` 等を除外している。
これで通常時は 0 件、出版社の文庫・新書フェアが始まったときだけ発火する。

手元で判定を試す:

```sh
./run.sh feed --dry                  # 既読状態を更新せず確認するだけ
./run.sh feed --dry --max-age=100000 # 期間を広げて発火経路の動作確認
```

既読管理は `.github/feed_state.json`（通知した記事の GUID のみ）。
検知したときだけ Actions がこのファイルを更新してコミットする。

### この構成の制約

- **RSS にプッシュはない。** 誰かが取りに行く必要があり、それを Actions にやらせている
  （HTTP 取得のみ・約 1 秒・public リポジトリなら無料枠）。
- **価格チェックは Actions では動かせない。** ライブラリの取得に Amazon のログイン
  セッションが要り、データセンター IP からのログインは CAPTCHA/2FA でまず通らない。
  macOS 通知も当然出せない。よって価格チェックは手元の Mac の役割。
- **蔵書リスト（`all_samples.json`）はリポジトリに置かない。** gitignore 済みで、
  Actions に渡すこともしていない。フィード監視に蔵書情報は不要。
- フィードは「どの本がセールか」を持っていない（記事本文も JS 描画で ASIN が取れない）。
  あくまで**きっかけ**であり、実際にどれが安いかは手元の価格チェックで判定する。
- 60 日間リポジトリに動きがないと、GitHub は定期ワークフローを自動停止する。

| `poc/2.3_all_samples.js` | ライブラリを全ページ巡回してサンプル書籍を収集 |
| `poc/2.4_batch.js` | 各書籍の価格・ポイント・紙価格を取得（404 は検索でフォールバック） |
| `poc/2.5_detect.js` | 前回スナップショットとの差分検知 → macOS 通知 |
| `poc/2.6_report.js` | 割引率順の表を Markdown / CSV で出力 |
| `poc/lib/amazon.js` | 商品ページ / Kindle 検索の共通操作 |
| `poc/lib/parsePrice.js` | 価格・ポイント抽出とセール判定 |
| `scripts/check_feed.js` | セール情報フィードの取得・キーワード判定・既読管理 |
| `feed.config.json` | 監視するフィードと発火キーワードの設定 |
| `.github/workflows/sale-watch.yml` | 1 時間ごとにフィードを確認し、該当があれば Issue を立てる |
| `run.sh` | 上記のランチャー |
| `discussion.md` | 設計の検討と PoC の全記録（DOM 構造・ハマりどころ） |

`2.1_evidence.js` / `2.3_inspect.js` / `2.4_price_inspect.js` は DOM 構造の調査用。

生成物はすべて `poc/out/`（gitignore 済み）に出る。ライブラリの内容やスクリーンショットを
含むためコミットされない。`.chrome-profile/` も同様。

## 実装上の要点

スクレイピングで詰まりやすかった点。詳細は `discussion.md`。

- **Kindle Unlimited 本の ￥0 問題** — KU 対象本はスワッチが `￥0 または￥561 (281pt)` となり、
  素朴に取ると ￥0 を拾う。`(NNNpt)` の直前の金額を購入価格とするルールで解決。
- **取り消し線 ≠ 値引き** — 商品ページの取り消し線は常時表示される「紙の本の価格」比較
  （`apex-basisprice`）や関連商品カルーセルのものが大半。買い物ボックス内にスコープを限定し、
  紙価格とカルーセルを除外して初めて本物の参考価格が取れる。
- **サンプル ASIN が 404** — 版・フォーマット差で `/dp/{ASIN}` が購入可能ページに解決しない本が
  149 冊中 6 件。タイトル検索（`/s?k=...&i=digital-text`、スポンサー除外）で別 ASIN に解決する。
- **detached Frame** — 長時間の一括処理中に page の実行コンテキストが切れて以降が連鎖失敗する。
  回復可能なエラーなら page を作り直して同一 ASIN を 1 回だけ再試行する。
- **`networkidle2` がハングする** — Amazon は接続が途切れないため、`domcontentloaded` + 固定 delay。

## 現状と残課題

PoC として「ログイン → サンプル一覧 → 価格取得 → セール判定 → 差分検知 → 通知」は一通り動く。

- 実際に Kindle 値引き中の本での参考価格 DOM の最終確認（手元のサンプルに値引き中の本が無かった）
- 404 フォールバック時、複数版（文庫 / 単行本 / e-book）からの最適候補選択（現状は先頭候補）
- 検知から価格チェックまでは人が `./run.sh all` を叩く必要がある（Mac 側に常駐を置きたくないため）
- 将来 AWS 等に置ければ、ログインセッションの持ち回りを解いて全自動にできる余地はある

## 注意

個人の蔵書を対象にした個人利用のスクレイピングツール。Amazon の DOM 変更で普通に壊れる。
アクセス間隔には delay を入れているが、実行頻度は常識の範囲で。
