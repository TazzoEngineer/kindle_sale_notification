# kindle_sale_notification

Kindle で **サンプルだけ落としてある「気になる本」** がセールになったら教えてくれるツール。

サンプルをダウンロードした本 ＝ 買うか迷っている本。そのリストを Amazon のライブラリから
自動で集めて、価格とポイント還元から**実質割引率**を出し、買い時を **macOS に通知**する。

蔵書ぜんぶを毎日クロールするのは重いので、**セール情報の RSS を GitHub Actions で見張り、
関係のありそうなセールが始まったときだけ手元で価格チェックを回す**構成にしている。

```
GitHub Actions（1時間毎・RSS だけ取得）
  └─ 文庫/新書/選書 などのキーワードに該当する新着記事を検知
       └─ Issue を立てて通知（メール / GitHub モバイル）
            └─ 手元の Mac で ./run.sh all → 実質割引率を計算 → macOS 通知
```

実行イメージ（数値は実行時点による）:

```
$ ./run.sh all
▶ 1/4 サンプル一覧を更新...
  [全書籍(ユニーク)] 196
  [全サンプル] 148
▶ 2/4 価格取得（148 件）...
  [1/148] B09HQJPY27 Kindle￥880 / 紙￥957 / 440pt 実質54% 🔥SALE(実質54%)  極夜行 (文春文庫)
  [2/148] B0H1GB6HSG Kindle￥2156 / 紙￥2200 / 22pt 実質3%  ノマドという生き方
  ...
  [セール中] 21 件（うち紙価格あり 20 件）
  [404] 0 件（フォールバック解決 2 件）/ [価格取得不可] 0 件
▶ 3/4 差分検知・通知...
  [通知対象] 2 件
  🔔 [B09HQJPY27] Kindle￥880 440pt 実質54%  極夜行 (文春文庫)
      理由: 新規セール / 値下がり ￥968→￥880
▶ 4/4 表を出力...
✅ 完了: out/report.md / report.csv
```

`report.md` は割引率の降順で並ぶ:

| 割引率 | 紙の本の価格 | Kindle価格 | 獲得ポイント | タイトル | 著者、訳者 | 発売日 |
| --- | --- | --- | --- | --- | --- | --- |
| 54% | ￥957 | ￥880 | 440pt | 極夜行 (文春文庫) | 角幡 唯介(著) | 2021/10/6 |
| 3% | ￥2,200 | ￥2,156 | 22pt | ノマドという生き方――旅暮らしの人類学 教養みらい選書 | 左地亮子(著) | 2026/6/10 |

## セールの判定基準

Kindle のセールは **値引きより「ポイント高還元」で行われることが多い**。
サンプル 149 冊を実測した回では、取り消し線による値引きは 0 件だったのに対し、
ポイント高還元（還元率 30〜50%）は 40 件あった。そこで値引きと還元を 1 つの指標に統合する。

```
実質割引率 = (紙の本の価格 − Kindle価格 + 獲得ポイント) / 紙の本の価格
セール     = 実質割引率 >= 20%          # src/lib/parsePrice.js の SALE_THRESHOLD
```

紙版が存在しない本は基準価格が無いので、ポイント還元率（ポイント / Kindle価格）で代替する。
通常の本は還元率 ~1%、高還元セールは 30〜50% と明確に分離できる。

差分検知（`./run.sh detect`）が通知するのは次の3つ。

| 種類 | 条件 |
| --- | --- |
| 新規セール | 今回セール中 かつ 前回は非セール |
| 値下がり | 今回の Kindle 価格 < 前回 |
| 割引率アップ | 実質割引率が前回 +10 ポイント以上 |

初回だけは比較対象が無いため、**その時点でセール中の本をまとめて通知**する
（`prices.json` と `price_history.json` の比較で、履歴が空の回は理由が「セール中」になる）。

## 動作環境

- **macOS**（通知に `osascript` を使う）
- **Node.js 18 以上**（`fetch` を使用。動作確認は v20）
- Chrome は Puppeteer が同梱版を落とすので別途インストール不要
- Amazon.co.jp のアカウント（初回に手動ログイン）
- セール検知（GitHub Actions）の受け取り方は2通り
  → [セール検知の受け取り方](#セール検知の受け取り方)

## セットアップ

```sh
npm install
./run.sh login        # 初回のみ。開いた Chrome で Amazon に手動ログイン（2FA も手動）→ Enter
./run.sh samples      # ライブラリを巡回してサンプル一覧を作る
```

ログインセッションはプロジェクト内の `.chrome-profile/` に永続化され、2 回目以降は不要。
普段使いの Chrome を終了する必要はない（専用プロファイルなので競合しない）。

## 使い方

```sh
./run.sh               # メニューから選択
./run.sh all           # 一覧更新 → 価格取得 → 差分検知・通知 → 表の出力
./run.sh samples       # ライブラリを巡回してサンプル一覧を更新
./run.sh batch 25      # 25 件だけ価格取得
./run.sh detect        # 前回との差分を検知して通知
./run.sh report        # 表（Markdown / CSV）を出力
./run.sh price B0CYZ95626   # 1 冊だけ価格を確認
./run.sh feed --dry    # セール情報フィードを手元で確認（Actions と同じ判定）
```

`./run.sh all` は **Chrome のウィンドウを開いて 10 分前後かかる**（Amazon がヘッドレスを
弾くため避けられない）。セール検知の通知を受けたときに回す想定。

個別の npm スクリプトは `package.json` を参照。
`npm run detect -- --dry` は通知も履歴更新もせず結果だけ表示する（状態を変えない確認用）。

## セール検知（GitHub Actions）

`.github/workflows/sale-watch.yml` が 1 時間ごとに RSS を取得し、
`feed.config.json` のキーワードに該当する**新着**記事があったときだけ Issue を立てる。
Issue は自分にアサインされるので、メールと GitHub モバイルに通知が飛ぶ。

立つ Issue はこんな内容:

```markdown
Kindle のセール情報フィードに、ウォッチ対象のキーワードを含む記事が出ました。

- [【講談社499円均一セール】明日まで！ 新書大賞にノミネートした作品など…](https://…)
  - 該当キーワード: 新書, 均一（Googleニュース）

---

手元の Mac で以下を実行すると、サンプル書籍の価格を取り直して差分を通知します。

    ./run.sh all
```

監視しているフィード（`feed.config.json` で変更可能）:

| フィード | 性格 |
| --- | --- |
| [きんどう](https://kindou.info/feed) | セール情報専門で速報性が高い。マンガ・ラノベ寄り |
| Google ニュース検索 | `Kindle セール (文庫 OR 新書 OR 学術)` のクエリ。メディア記事を拾う |
| はてなブックマーク検索 | 個人ブログのセール紹介記事を拾う |

**キーワードの設計が肝心。** 「50%還元」のような語はマンガのセール記事にほぼ毎回付くため、
1日 6〜10 回発火してしまう（実測で 20 件中 9 件が該当）。既定では
`文庫 / 新書 / 選書 / 学術文庫 / ブルーバックス / 岩波 / 早川 / 文春 / 新潮 / 均一 / 半額` など
**自分が読む帯**に寄せ、`ラノベ / 異世界 / コミック` 等を除外している。
これで通常時は 0 件、出版社の文庫・新書フェアが始まったときだけ発火する。

手元で判定を試す:

```sh
./run.sh feed --dry                  # 既読状態を更新せず確認するだけ
./run.sh feed --dry --max-age=100000 # 期間を広げて発火経路の動作確認
```

既読管理は `.github/feed_state.json`（通知した記事の GUID のみ、最大 300 件）。
検知したときだけ Actions がこのファイルを更新してコミットする。

### セール検知の受け取り方

立つ Issue には個人情報は入らない（「こういうセール記事が出た」だけ）。
自分で回すか、誰かが回しているものを見せてもらうか、どちらでもよい。

#### A. 誰かのリポジトリを Watch する（セットアップ不要）

Watch → Custom → **Issues** にチェックすれば、所有者でなくても新規 Issue のたびに
メール / GitHub モバイルに通知が届く。fork も Actions の設定もいらない。

- キーワードはそのリポジトリの `feed.config.json` 次第なので、自分の読書傾向には寄せられない
- 相手がワークフローを止めたら通知も止まる
- GitHub の通知を使いたくないなら、`https://github.com/<owner>/<repo>/commits/master.atom` を
  RSS リーダーで購読してもよい。検知時に `feed_state.json` がコミットされるので、
  これがそのまま検知のフィードになる（Issue 自体の Atom フィードは提供されていない）

#### B. 自分のアカウントで回す（キーワードを自分用に調整できる）

1. このリポジトリを fork する（または自分のリポジトリとして push する）
2. Actions タブを開き、Actions を有効にする
3. **fork では定期実行が既定で止まっている**ので、`Kindle セール監視` ワークフローの
   ページで有効化する
4. `feed.config.json` のキーワードを自分の読書傾向に合わせて書き換える
5. `Run workflow` で手動実行し、`[検知] 0 件` などのログが出れば動いている

注意点:

- Issue は `github.repository_owner`（リポジトリの所有者）にアサインされる。
  自分のリポジトリなら、Watch の設定に関係なく確実に通知が届く。
- 定期実行（cron）は**デフォルトブランチでしか動かない**。このリポジトリでは `master`。
- 検知時にワークフローが `.github/feed_state.json` をコミットするため、書き込み権限が要る。
  `permissions:` で `contents: write` / `issues: write` を宣言済み。

なお、どちらの場合も**価格チェックは手元の Mac で回す**（検知はきっかけにすぎず、
自分の蔵書のどれが安くなったかはローカルでしか判定できない）。

### この構成の制約

- **RSS にプッシュはない。** 誰かが取りに行く必要があり、それを Actions にやらせている
  （HTTP 取得のみ・約 1 秒・public リポジトリなら無料枠）。
- **価格チェックは Actions では動かせない。** ライブラリの取得に Amazon のログイン
  セッションが要り、データセンター IP からのログインは CAPTCHA/2FA でまず通らない。
  macOS 通知も当然出せない。よって価格チェックは手元の Mac の役割。
- **蔵書リスト（`all_samples.json`）はリポジトリに置かない。** gitignore 済みで、
  Actions に渡すこともしていない。フィード監視に蔵書情報は不要。
- フィードは「どの本がセールか」を持っていない（記事本文も JS 描画で ASIN が取れない）。
  あくまで**きっかけ**であり、実際にどれが安いかは手元の価格チェックで判定する。
- GitHub の cron は数分〜十数分遅れることがある。また 60 日間リポジトリに動きがないと、
  GitHub は定期ワークフローを自動停止する。

## 構成

```
run.sh                  すべての入口。メニューと各サブコマンド
src/
  steps/                通常フローの各段階（run.sh から順に呼ばれる）
    login.js            ログイン（専用プロファイル + 手動 2FA）
    samples.js          ライブラリを全ページ巡回してサンプル書籍を収集
    prices.js           各書籍の価格・ポイント・紙価格を取得（404 は検索でフォールバック）
    price.js            1 冊だけ価格を確認
    detect.js           前回スナップショットとの差分検知 → macOS 通知
    report.js           割引率順の表を Markdown / CSV で出力
  feed/
    check_feed.js       セール情報フィードの取得・キーワード判定・既読管理
  lib/                  共通モジュール
    amazon.js           商品ページ / Kindle 検索の共通操作
    parsePrice.js       価格・ポイント抽出とセール判定
  tools/                DOM 構造の調査用（通常フローでは使わない）
    inspect_library.js  ライブラリ一覧の DOM ダンプ
    inspect_price.js    商品ページの価格まわりの DOM ダンプ
    search_fallback.js  タイトル検索での ASIN 解決を単体で試す
    evidence.js         ログイン済みであることのスクリーンショット取得
    samples_page1.js    1 ページ目だけのサンプル抽出（samples.js の原型）
out/                    生成物（gitignore）
feed.config.json        監視するフィードと発火キーワードの設定
discussion.md           設計の検討と作業の全記録（DOM 構造・ハマりどころ）
.github/workflows/sale-watch.yml
                        1 時間ごとにフィードを確認し、該当があれば Issue を立てる
```

生成物はすべて `out/`（gitignore 済み）に出る。

| ファイル | 内容 |
| --- | --- |
| `all_books.json` / `all_samples.json` | ライブラリの全書籍 / サンプルのみ |
| `prices.json` / `prices_onsale.json` | 直近の価格取得結果 / うちセール中 |
| `price_history.json` | 差分検知のための前回スナップショット |
| `notifications.json` | 直近の通知内容 |
| `report.md` / `report.csv` | 割引率順の表（CSV は Excel 用に BOM 付き） |
| `feed_matched.json` / `feed_summary.md` | フィード検知の結果 |

蔵書の内容やスクリーンショットを含むためコミットされない。`.chrome-profile/` も同様。

## 実装上の要点

スクレイピングで詰まりやすかった点。詳細は `discussion.md`。

- **Kindle Unlimited 本の ￥0 問題** — KU 対象本はスワッチが `￥0 または￥561 (281pt)` となり、
  素朴に取ると ￥0 を拾う。`(NNNpt)` の直前の金額を購入価格とするルールで解決。
- **取り消し線 ≠ 値引き** — 商品ページの取り消し線は常時表示される「紙の本の価格」比較
  （`apex-basisprice`）や関連商品カルーセルのものが大半。買い物ボックス内にスコープを限定し、
  紙価格とカルーセルを除外して初めて本物の参考価格が取れる。
- **サンプル ASIN が 404** — 版・フォーマット差で `/dp/{ASIN}` が購入可能ページに解決しない本が
  149 冊中 6 件あった。タイトル検索（`/s?k=...&i=digital-text`、スポンサー除外）で別 ASIN に解決する。
- **detached Frame** — 長時間の一括処理中に page の実行コンテキストが切れて以降が連鎖失敗する。
  回復可能なエラーなら page を作り直して同一 ASIN を 1 回だけ再試行する。
- **`networkidle2` がハングする** — Amazon は接続が途切れないため、`domcontentloaded` + 固定 delay。
- **はてブの RSS は日付が `dc:date`** — RSS 1.0(RDF) 形式のため `pubDate` だけ見ていると
  日付が取れず、数年前の記事が「新着」として通過する。

## 困ったときは

| 症状 | 対処 |
| --- | --- |
| `./run.sh all` が「サンプルが 0 件」で止まる | Amazon のセッション切れ。`./run.sh login` で入り直す |
| Chrome が起動しない / プロファイルロック | 同じ `.chrome-profile/` を使うので**同時に 2 つ走らせない** |
| 価格が `null` の本がある | 商品ページのレイアウト差。`./run.sh price <ASIN>` で単体確認できる |
| `prices.json` が一部しか無い | `--start` / `--limit` の部分実行はその範囲で**上書き**する。全件が要るときは `./run.sh all` |
| Actions が動いていない | 60 日無活動で自動停止する。Actions タブから手動で有効化・実行できる |
| 検知が多すぎる / 少なすぎる | `feed.config.json` の `keywords` / `excludeKeywords` を調整する |
| フィードの判定を試したい | `./run.sh feed --dry --max-age=100000`（既読状態を変えずに確認） |

## 現状と残課題

「セール情報の検知 → ログイン → サンプル一覧 → 価格取得 → セール判定 → 差分検知 → 通知」
までが一通り動く。

- 実際に Kindle 値引き中の本での参考価格 DOM の最終確認（手元のサンプルに値引き中の本が無かった）
- 404 フォールバック時、複数版（文庫 / 単行本 / e-book）からの最適候補選択（現状は先頭候補）
- 検知から価格チェックまでは人が `./run.sh all` を叩く必要がある（Mac 側に常駐を置きたくないため）
- 将来 AWS 等に置ければ、ログインセッションの持ち回りを解いて全自動にできる余地はある

## 注意

個人の蔵書を対象にした個人利用のスクレイピングツール。Amazon の DOM 変更で普通に壊れる。
アクセス間隔には delay を入れているが、実行頻度は常識の範囲で。
